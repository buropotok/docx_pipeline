3) Обновлённые правила реконструктора (для reconstructor_contract.md)

Ниже формулировки, которые можно почти напрямую вставлять в контракт.

3.1 Термины

Управляемый блок: block-level SDT в document.xml (w:sdt), у которого w:sdtPr/w:tag/@w:val == <id>.

Passthrough: любой узел, который не является управляемым блоком (или не имеет нашей метки).

3.2 Основные принципы

Управляемость

Реконструктор применяет patch-операции только к управляемым блокам.

Passthrough-узлы не удаляются и не перестраиваются.

Patch-mode

Массив content может быть неполным описанием документа.

Отсутствие элемента в content не означает удаления и не влияет на passthrough.

No synthetic

Реконструктор не “додумывает” форматирование и структуру.

Любые изменения должны следовать только из donor XML, из clone (derive_from), либо из явно заданных полей элемента (которые и есть overrides).

3.3 Детерминированный порядок применения

Реконструктор выполняет шаги в фиксированном порядке:

A) Индексация

Построить отображение id -> sdtNode по всем управляемым блокам в целевом контейнере (минимум w:body; позже — w:tc).

B) Удаления

Для каждого элемента из content с deleted:true:

если id найден среди управляемых блоков → удалить целый w:sdt;

если id не найден → ошибка/варнинг (по режиму), но никаких удалений “по аналогии”.

C) Вставки/перемещения (позиционирование)

Для каждого элемента из content в порядке следования:

если у элемента заданы anchor+position:

найти управлямый блок anchor (SDT tag=anchor). Если нет → ошибка патча (операция не применяется).

обеспечить наличие блока для id:

если id уже существует → это move (перемещение) в заданную позицию.

если id не существует → create:

если derive_from задан → создать новый w:sdt с tag=id, поместив внутрь clone donor-элемента derive_from (его w:p/w:tbl без изменений).

иначе → ошибка (нет способа создать без синтетики).

вставить/переместить блок в позицию:

position="before" → непосредственно перед anchor, ниже любых passthrough, стоящих перед anchor.

position="after" → непосредственно после anchor, выше любых passthrough, стоящих после anchor.

если несколько элементов с position=before к одному anchor — они вставляются в порядке следования в content (это и есть детерминизм).

D) Модификации (overrides)

Для всех существующих/созданных управляемых блоков, которые есть в content и не deleted:true:

применить изменения, описанные в самих полях элемента (runs, p_format, tblPr, tcPr, …).

изменение должно быть минимальным: не пересобирать w:p целиком, если override не требует (чтобы не терять поля/закладки/гиперссылки).

3.4 Инварианты / ошибки

anchor всегда должен ссылаться на существующий управляемый id (валидируется модификатором; реконструктор фейлится детерминированно).

id должен быть уникальным среди управляемых блоков. Коллизия = ошибка.

Реконструктор никогда не удаляет и не перемещает passthrough
