# Reconstructor Contract (Business + Technical API)

Документ описывает фактические возможности `src/reconstructor.py` на двух уровнях:
1) бизнес-уровень (понятный пользователю Word),
2) технический API-уровень (что именно передавать в RAW JSON для нужного результата).

---

## Часть 1. Бизнес-контракт реконструктора

### 1. Что делает реконструктор
Реконструктор не создает документ с нуля. Он берет существующий DOCX-донор и вносит в него изменения по RAW JSON-инструкции:
- удаляет блоки,
- переставляет блоки,
- добавляет блоки копированием,
- меняет оформление абзацев,
- полностью заменяет содержимое абзацев,
- меняет таблицы (таблицу, строки, ячейки, абзацы внутри ячеек),
- вставляет изображения.

Поддерживаемые корневые блоки документа:
- абзац;
- таблица.

### 2. Операции с корневыми блоками (абзацы/таблицы)

#### 2.1 Удаление
Можно удалить абзац или таблицу целиком по идентификатору.

#### 2.2 Перемещение
Можно переставить существующий абзац или таблицу:
- перед указанным блоком;
- после указанного блока.

#### 2.3 Добавление нового блока
Можно добавить новый абзац или таблицу через копирование существующего блока-образца и применение изменений.

### 3. Что можно менять в абзаце

#### 3.1 Параметры абзаца
Реконструктор умеет изменять:

1) Выравнивание абзаца:
- по левому краю;
- по центру;
- по правому краю;
- по ширине;
- распределенное.

2) Вертикальное положение строки в абзаце:
- автоматически;
- по базовой линии;
- по верхнему краю;
- по центру;
- по нижнему краю.

3) Отступы:
- слева;
- справа;
- отступ первой строки;
- выступ (обратный отступ первой строки).

4) Интервалы:
- перед абзацем;
- после абзаца;
- межстрочный интервал;
- интервал перед в строках;
- интервал после в строках;
- автоматический интервал перед;
- автоматический интервал после;
- правило межстрочного интервала:
  - автоматически;
  - точно;
  - не менее.

5) Параметры разбиения по страницам:
- не отрывать от следующего абзаца;
- не разрывать строки текущего абзаца;
- начинать с новой страницы;
- контроль висячих строк;
- не добавлять интервал между абзацами одного стиля;
- привязка к сетке документа.

6) Позиции табуляции:
- позиция;
- тип табуляции;
- заполнитель.

7) Нумерация/маркеры:
- принадлежность к списку;
- уровень списка.

#### 3.2 Содержимое абзаца
Реконструктор полностью перестраивает содержимое абзаца из последовательности фрагментов.

Поддерживаемые фрагменты:
- обычный текст;
- знак табуляции;
- разрыв;
- перевод каретки;
- специальный символ;
- изображение.

#### 3.3 Форматирование текста внутри фрагмента
Для каждого фрагмента можно задать:
- полужирный;
- курсив;
- зачеркнутый;
- двойное зачеркивание;
- все прописные;
- малые прописные;
- подчеркивание;
- цвет текста;
- цвет выделения;
- верхний/нижний индекс;
- размер шрифта;
- семейства шрифтов для разных письменностей;
- язык.

#### 3.4 Пробелы в тексте
Если текст начинается пробелом, заканчивается пробелом или содержит двойные пробелы, реконструктор сохраняет их как значимые.

### 4. Что можно менять в таблицах

#### 4.1 На уровне таблицы
Можно менять:
- стиль таблицы;
- ширину и тип ширины;
- выравнивание;
- отступ;
- межъячеечный интервал;
- границы таблицы;
- внутренние поля ячеек таблицы;
- режим компоновки;
- параметры оформления первой/последней строки и первого/последнего столбца, полосатых строк и столбцов;
- ширины колонок сетки таблицы.

#### 4.2 На уровне строки
Можно:
- менять порядок строк;
- добавлять строку копированием;
- менять свойства строки:
  - высота;
  - правило высоты;
  - строка заголовка;
  - запрет разрыва строки;
  - выравнивание содержимого строки.

#### 4.3 На уровне ячейки
Можно менять:
- ширину;
- горизонтальное объединение;
- вертикальное объединение;
- границы;
- заливку;
- внутренние поля;
- вертикальное выравнивание содержимого;
- направление текста;
- режим «уместить текст»;
- режим «не переносить текст».

#### 4.4 Абзацы внутри ячейки
Внутри ячейки можно:
- удалять абзацы;
- перемещать абзацы перед/после другого абзаца в той же ячейке;
- добавлять абзацы копированием существующего абзаца в той же ячейке;
- заменять содержимое абзацев, включая форматирование текста и изображения.

### 5. Работа с изображениями
Изображение вставляется в текст, если в данных уже есть:
- корректная ссылка на существующую связь изображения;
- ширина и высота.

### 6. Границы возможностей
Сейчас не поддерживается реконструкция:
- фигур;
- мягкого переноса как отдельного типа фрагмента;
- неразрывного дефиса как отдельного типа фрагмента.

Также реконструктор не создает новые связи изображений с нуля: используется уже существующая связь.

## Часть 2. Технический API-контракт

## 1) Запуск
```bash
python src/reconstructor.py --in-json <raw.json> --out-docx <out.docx> --donor-docx <donor.docx>
```

Параметры обязательны:
- `--in-json` — входной RAW JSON;
- `--out-docx` — путь выходного DOCX;
- `--donor-docx` — донорский DOCX с разметкой идентификаторов.

## 2) Обязательные разделы RAW
На верхнем уровне JSON обязательны:
- `meta`
- `document_info`
- `numbering_definitions`
- `doc_defaults`
- `styles`
- `content`

## 3) Общие правила patch-операций по `content`

Каждый элемент `content` — это либо абзац, либо таблица.

### 3.1 Удаление
Передайте:
- `id`
- `deleted: true`

### 3.2 Перемещение существующего элемента
Передайте:
- `id` существующего элемента
- `anchor` — идентификатор якоря
- `position` — `before` или `after`

### 3.3 Вставка нового элемента
Передайте:
- новый `id` (признак нового элемента — окончание `.число`)
- `derive_from` — идентификатор элемента-образца
- `anchor` + `position` для места вставки

Если у нового элемента нет `derive_from`, реконструктор завершится ошибкой.

## 4) Правила `anchor` + `position` и порядок

- Элементы с позиционированием группируются по паре (`anchor`, `position`).
- Группы обрабатываются в порядке первого появления в `content`.
- Внутри группы порядок вставки соответствует порядку элементов в `content`.

Практическое правило:
если нужно вставить несколько блоков подряд после одного якоря в фиксированном порядке — задавайте им одинаковые `anchor` и `position`, а в массиве `content` располагайте в нужной последовательности.

## 5) API абзаца

Обязательные поля абзаца:
- `type: "paragraph"`
- `id`
- `p_style_id`
- `runs`

Опциональные patch-поля:
- `deleted`
- `anchor`
- `position`
- `derive_from`
- `p_format`

Важно:
`p_format` применяется только если в абзаце донора уже существует блок свойств абзаца.

## 6) API параметров абзаца (`p_format`)

Поддерживаются:
- выравнивание;
- вертикальное положение строки в абзаце;
- отступы;
- интервалы и правило интервала;
- флаги разбиения/поведения;
- табуляции;
- сведения о списке.

Рекомендация:
передавайте только те поля, которые требуется изменить.

## 7) API текстовых фрагментов (`runs`)

Поддерживаемые типы для реконструкции:
- `text`
- `tab`
- `break`
- `cr`
- `sym`
- `picture`

### 7.1 Для типа `text`
Требуется поле `text`.

### 7.2 Для типа `break`
Дополнительно можно передать тип разрыва.

### 7.3 Для типа `picture`
Требуется:
- `file`
- `relation_id`
- `extent.cx`
- `extent.cy`

Если `relation_id` отсутствует или отсутствуют размеры, реконструктор завершится ошибкой.

## 8) API таблицы

Обязательные поля таблицы:
- `type: "table"`
- `id`
- `rows`

Опциональные:
- `deleted`
- `anchor`
- `position`
- `derive_from`
- свойства таблицы
- сетка таблицы

## 9) API строк таблицы

Для каждой строки:
- обязательны `id`, `cells`
- для новой строки обязателен `derive_from`
- новая строка определяется по окончанию `id` на `.число`

## 10) API ячеек таблицы

Для ячейки:
- обязательное поле: `content` (массив абзацев)
- опционально: свойства ячейки

Важно:
количество ячеек в JSON для строки должно точно совпадать с количеством ячеек в донорской строке.

## 11) API абзацев внутри ячеек

Поддерживаются операции:
- удаление (`deleted: true`)
- перемещение (`anchor` + `position`)
- добавление нового абзаца (`id` с окончанием `.число` + `derive_from`)

Правило целостности:
внутри ячейки поля `anchor` и `position` должны передаваться парой: либо оба есть, либо оба отсутствуют.

## 12) Частые ошибки (и как избежать)

1. **Не найден якорь**
   - Убедитесь, что `anchor` существует в соответствующей области (корень документа или конкретная ячейка).

2. **Новый элемент без `derive_from`**
   - Для всех новых элементов (абзац, таблица, строка, абзац в ячейке) обязательно передайте `derive_from`.

3. **Несовпадение числа ячеек в строке таблицы**
   - Количество `cells` в JSON должно совпадать с донором.

4. **Некорректная картинка**
   - Передайте существующий `relation_id` и оба размера (`cx`, `cy`).

5. **Передан только один из пары `anchor`/`position` внутри ячейки**
   - Передавайте оба поля вместе.

## 13) Практический минимум для предсказуемого результата

Чтобы гарантированно выполнить редактирование:
1. Используйте корректные идентификаторы элементов донора.
2. Для новых элементов используйте шаблон `id` с окончанием `.число`.
3. Для новых элементов всегда задавайте `derive_from`.
4. Для перемещений всегда задавайте `anchor` и `position` вместе.
5. Для таблиц соблюдайте точное число ячеек в строках.
6. Для изображений используйте существующую связь и реальные размеры.
7. Проверяйте JSON на соответствие схеме перед запуском.
