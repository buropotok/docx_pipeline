Глоссарий

Буду использовать только эти термины.

1. left_base

Параметр схемы: indent_start_twip
Маркер в Word: нижний прямоугольник
Смысл: базовый левый отступ абзаца.

Это не “первая строка” и не “остальные строки”, а именно базовая опорная позиция абзаца.

2. first_line_delta

Параметр схемы: indent_first_line_twip
Маркер в Word: участвует в положении верхнего треугольника, если не используется hanging
Смысл: дополнительное смещение первой строки относительно left_base.

Если first_line_delta > 0, первая строка правее базы.
Если first_line_delta < 0, первая строка левее базы.

3. hanging_delta

Параметр схемы: indent_hanging_twip
Маркер в Word: участвует в положении нижнего треугольника, если используется hanging
Смысл: смещение не первой строки относительно первой строки / базы в представлении hanging.

4. first_line_marker

Не поле схемы, а вычисляемая величина
Маркер в Word: верхний треугольник
Смысл: реальная x-координата начала первой строки.

Это главный параметр для нашей логики отрицательного отступа.

Считается так:

если hanging_delta != 0, то
first_line_marker = left_base - hanging_delta

иначе
first_line_marker = left_base + first_line_delta

5. other_lines_marker

Не поле схемы, а вычисляемая величина
Маркер в Word: нижний треугольник
Смысл: реальная x-координата начала второй и последующих строк.

Считается так:

если hanging_delta != 0, то
other_lines_marker = left_base

иначе
other_lines_marker = left_base

То есть в твоей модели left_base совпадает с нижним треугольником.

6. anchor

Якорь — любой юнит, позиция которого должна сохраняться.
Это текстовый фрагмент, объект, спецсимвол — всё, что не является “чистым промежутком”.

Главное правило:

координаты якорей после оптимизации не должны меняться.

7. anchor_x_start, anchor_x_end

Абсолютные координаты якоря в строке.

anchor_x_start — где якорь начинается

anchor_x_end — где якорь заканчивается

Они считаются один раз по исходной строке и дальше становятся источником правды.

8. leading_spaces

Непрерывная группа обычных пробелов в начале строки до первого якоря.

Только пробелы. Не табы.

9. inline_spacer

Обычный текстовый run с одним пробелом и r_format.spacing_twip, который используется вместо таба там, где таб не может корректно сохранить координаты.

Как это выглядит на Word-линейке

верхний треугольник = first_line_marker

нижний треугольник = other_lines_marker

нижний прямоугольник = left_base

То есть для первой строки всегда смотрим только на верхний треугольник.

Пример словами

Пусть:

left_base = 0

hanging_delta = 300

Тогда:

other_lines_marker = 0

first_line_marker = 0 - 300 = -300

Это значит:

верхний треугольник стоит в минусе

нижний треугольник стоит в нуле

первая строка начинается левее нуля

остальные строки — от нуля

Это и есть отрицательная первая строка.

Если в начале строки есть 500 twips пробелов, а первый якорь начинается на +200, то после удаления этих пробелов мы обязаны так перестроить строку, чтобы этот якорь всё равно начинался на +200, а не “примерно около нуля”.

Принцип перестройки алгоритма

Алгоритм надо строить в две фазы.

Фаза A. Снять геометрию исходной строки

Сначала ничего не меняем. Только измеряем.

Для каждой строки:

вычисляем:

left_base

first_line_delta

hanging_delta

first_line_marker

other_lines_marker

раскладываем runs в units

один раз считаем абсолютные координаты всех юнитов от first_line_marker

как только находим якорь — сразу записываем его координаты в словарь

Например:
anchor_map[unit_idx] = {
    "start": start_x,
    "end": end_x,
    "width": width_x,
}
  И дальше уже никогда не пересчитываем исходные координаты якоря из мутирующих данных.  Это и есть источник правды.  
Фаза B. Перестроить строку под инвариант якорей  После этого можно менять:  пробелы  табы  first_line_marker  представление отступа в p_format  Но нельзя менять координаты якорей.  Новый каркас алгоритма для negative first line 
Шаг 1. Определяем первый якорь  Берём первый якорь из словаря координат:  first_anchor_start = anchor_positions[first_anchor_id]["start"]  first_anchor_end = anchor_positions[first_anchor_id]["end"]  И отдельно измеряем:  leading_spaces_width  
Шаг 2. Классифицируем случай  Классификация делается только по исходным координатам якоря.  
Случай A  first_anchor_start < 0 и first_anchor_end > 0  Первый якорь пересекает ноль.  
Если есть leading_spaces: 
 удаляем leading spaces  
новый first_line_marker = first_anchor_start   
Дальше все gap после первого якоря — обычный tab.  

Если leading spaces нет:  ничего не трогаем в начале  first_line_marker не меняем 

 Случай B  first_anchor_start < 0 и first_anchor_end <= 0  Первый якорь целиком в отрицательной зоне.  
Если есть leading_spaces:  
удаляем leading spaces  
новый first_line_marker = новый first_line_marker = first_anchor_start    
 первый gap после первого якоря строим через inline_spacer  
все последующие gap — через tab  

Если leading spaces нет:  
first_line_marker не трогаем
  первый gap после первого якоря строим через inline_spacer  
все последующие gap — через tab  

  Случай C  first_anchor_start >= 0  Первый якорь уже в положительной зоне.  

Если есть leading_spaces:  
удаляем leading spaces  ставим first_line_marker = 10  твипс 
вставляем в начало tab, но его позицию считаем не по ширине пробелов, а по координате первого якоря  first_anchor_start 
Ключевая формула:  leading_tab_stop = first_anchor_start  Потому что после перестройки первый якорь должен снова попасть ровно в ту же абсолютную координату.  Не “примерно”, не “через old indent + gap”, а именно в сохранённый first_anchor_start.
